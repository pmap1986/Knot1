# Retos de la S3 · Clases y capas

Hoy convertimos las pruebas "espagueti" en un framework por capas. Son 5 retos cortos: cada uno es completar **un método** de 3 a 10 líneas.

## Antes de empezar: cómo funcionan los retos

Cada reto es un método que hoy no hace nada y lanza este error:

```
PENDIENTE (S3): completa PaginaLogin.ingresar — ver retos/S03.md, reto 1
```

Dentro del método hay un comentario `TODO` con los pasos y una pista. Escribes el código, **borras la línea `throw`** y corres las pruebas del reto. Si quedan en verde, terminaste.

| Ruta | Cómo editas | Cómo revisas |
|---|---|---|
| 1 · En tu equipo | VS Code o el Bloc de notas | `npm.cmd run retos:s03` |
| 2 · En la nube | En GitHub, abre el archivo y pulsa el lápiz ✏️. Al terminar, **Commit changes** | Pestaña **Actions** → la última corrida → resumen y `evidencias.html` |
| 3 · Solo navegador | Lee el reto y escribe tu solución en el chat o en papel | Compara con la solución que mostramos al cierre |

Para correr un solo reto en tu equipo: `npx.cmd playwright test reto1 --project=retos-s03`

## Calentamiento (10 min): ¿qué duele del espagueti?

Abre [`tests/antes/espagueti.spec.ts`](../tests/antes/espagueti.spec.ts). Las 5 pruebas pasan.

1. Cuenta cuántas veces aparece `getByLabel('Usuario')` y cuántas `'Clave123'`.
2. Si el botón **Ingresar** cambia a **Entrar**, ¿cuántas líneas corriges?
3. Ahora abre [`tests/ui/inicio.spec.ts`](../tests/ui/inicio.spec.ts). ¿Dónde quedaron los localizadores?

Respuesta: en [`src/paginas/PaginaInicio.ts`](../src/paginas/PaginaInicio.ts). Esa clase está completa: **es tu modelo para los retos**.

## Las 6 ideas de clases, en este repo

| Idea | En una frase | Dónde verla |
|---|---|---|
| Clase | El molde | `export class PaginaInicio` |
| Objeto | Lo que sale del molde | `new PaginaInicio(page)` (lo hace el fixture) |
| Constructor | Lo que la clase necesita para existir | `constructor(page: Page)` |
| Herencia | La hija recibe lo del padre | `PaginaLogin extends PaginaBase` |
| Polimorfismo | El mismo método hace algo distinto en cada hija | `abrir()` usa la `ruta` de cada página |
| Encapsulamiento | Lo interno queda escondido | localizadores `private`, token `private` |

## Reto 1 · `PaginaLogin.ingresar` — encapsulamiento

**Archivo:** [`src/paginas/PaginaLogin.ts`](../src/paginas/PaginaLogin.ts)

Los tres localizadores ya están en el constructor y son `private`: la prueba no los ve. Completa `ingresar(usuario, clave)` para que escriba el usuario, la clave y pulse **Ingresar**.

**Pista:** `await this.campoUsuario.fill(usuario);` es la primera de tres líneas.

**Revisa:** `npx.cmd playwright test reto1 --project=retos-s03` → 2 pruebas en verde.

**Para conversar:** la prueba dice `paginaLogin.ingresar('ana', 'Clave123')`. Si el campo cambia de nombre, ¿qué archivo tocas?

## Reto 2 · `PaginaOtp.validar` — herencia

**Archivo:** [`src/paginas/PaginaOtp.ts`](../src/paginas/PaginaOtp.ts)

Completa `validar(codigo)`: escribe el código y pulsa **Validar**.

**Pista:** es como el reto 1, con un solo campo.

**Revisa:** `npx.cmd playwright test reto2 --project=retos-s03`. La segunda prueba usa `paginaOtp.mensajeDeError`. Busca ese nombre en `PaginaOtp.ts`: no está. ¿De dónde sale? (De `PaginaBase`: eso es herencia.)

## Reto 3 · `PaginaTransferir.transferir` — un método con decisiones

**Archivo:** [`src/paginas/PaginaTransferir.ts`](../src/paginas/PaginaTransferir.ts)

El método recibe un objeto `{ origen, destino, monto, aceptar4x1000 }`. Completa los 4 pasos del `TODO`.

**Pistas:**
- `fill()` recibe texto: `this.campoMonto.fill(String(monto))`.
- Para lo opcional usa `if`: `if (origen) { await this.listaOrigen.selectOption(origen); }`

**Revisa:** `npx.cmd playwright test reto3 --project=retos-s03` → 3 en verde y 1 **hallazgo esperado**: con tu código, la prueba del monto exacto de $1.000 encuentra un bug real del banco (BUG-01). Esa prueba describe lo correcto y queda marcada con `hallazgoEsperado`: falla a propósito mientras el bug exista.

## Reto 4 · `ClienteBanco.transferir` — la capa de API

**Archivo:** [`src/api/ClienteBanco.ts`](../src/api/ClienteBanco.ts)

Completa `transferir(origen, destino, monto)`: un `POST` a `/api/transferencias` que devuelve `{ estado, datos }`.

**Pista:** copia el cuerpo de `login()`, cambia la ruta y los datos, y agrega `headers: this.encabezados()`. Ese método privado pone el token: la prueba nunca lo ve (encapsulamiento).

**Revisa:** `npx.cmd playwright test reto4 --project=retos-s03` → 2 en verde y 1 hallazgo esperado (BUG-02: desde Corriente, el 4x1000 no se descuenta del saldo).

## Reto 5 · `iniciarSesionPorUi` — la capa de flujos

**Archivo:** [`src/flujos/sesion.ts`](../src/flujos/sesion.ts) · **Necesita los retos 1 y 2.**

Une las piezas: login → esperar la pantalla del código → leer el código en el buzón → validar → esperar la pantalla de inicio. Cada paso es una línea con `await`; el `TODO` las describe.

**Pista:** las páginas llegan en el objeto `paginas`: `paginas.login`, `paginas.otp`, `paginas.buzon`, `paginas.inicio`.

**Revisa:** `npx.cmd playwright test reto5 --project=retos-s03` → 2 en verde.

**Para conversar:** `abrirConSesion` (en el mismo archivo) entra por API y es más rápido. ¿Cuándo usarías cada uno?
